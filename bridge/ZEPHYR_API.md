# Контракт: что Zephyr ждёт от моста

Спецификация для того, кто пишет мост. Zephyr обращается к мосту точно так же, как к OpenAI,
поэтому ничего специфичного изобретать не нужно — но есть четыре места, где расхождение
ломает всё молча.

## Эндпоинт

```
POST <base>/v1/chat/completions
Authorization: Bearer <BRIDGE_TOKEN>
Content-Type: application/json
```

`BRIDGE_TOKEN` — то, что пользователь вписал в поле «API ключ». Проверяй его **до** обращения
к провайдеру: адрес на Vercel угадывается, и квоту потратит тот, кто его нашёл.

## Запрос

```json
{
  "model": "glm-5.3",
  "messages": [
    { "role": "system",    "content": "…" },
    { "role": "user",      "content": "…" },
    { "role": "assistant", "content": "…" }
  ],
  "temperature": 0.7,
  "max_tokens": 2048,
  "stream": true,
  "stream_options": { "include_usage": true },
  "tools": [ … ],
  "tool_choice": "auto"
}
```

`model` можно игнорировать и подставлять свою — Zephyr не возражает.

## Ответ при `stream: true`

`Content-Type: text/event-stream`, строки вида `data: {…}`, в конце `data: [DONE]`.

Zephyr читает из каждого кадра:

| Поле | Что делает |
|---|---|
| `choices[0].delta.content` | дописывается в пузырь ответа |
| `choices[0].delta.reasoning_content` | показывается в блоке «Размышления модели» |
| `choices[0].delta.tool_calls` | накапливается по `index`, см. ниже |
| `choices[0].finish_reason` | `tool_calls` → Zephyr выполнит инструменты и пришлёт ещё один запрос |
| `usage.total_tokens` | счётчик токенов под ответом (шлётся последним кадром) |

## Ответ при `stream: false`

Обычный JSON: `choices[0].message.content`, плюс `usage`, если есть.

## Ошибки

**Отдавай реальный HTTP-код**, не заворачивай всё в 200. Zephyr разбирает их и показывает
человеку, что делать: 401 → «проверьте ключ», 404 → «проверьте адрес и имя модели»,
429 → читает заголовок `Retry-After` и **сам повторяет один раз**, если там меньше 60 секунд.
Тело ошибки — `{"error": {"message": "…"}}`, текст показывается пользователю.

## Два места, где легко разойтись

### 1. Инструменты — чьи?

Если у моста **свой цикл SEARCH/READ**, а Zephyr при этом шлёт `tools` — вы будете искать
в интернете дважды, каждый по-своему, и ответы станут непредсказуемыми.

Выбери одно:

- **Мост ищет сам** → пользователь выключает в Zephyr «Настройки → ИИ Помощник → Доступ
  в интернет». Тогда `tools` не приходят, и мост полный хозяин.
- **Zephyr управляет поиском** → мост просто пробрасывает `tools` и `tool_calls` насквозь.
  Zephyr сам выполнит `web_search` / `open_page` и пришлёт результаты следующим запросом.

Первый вариант лучше, если у моста поиск умнее. Второй — если хочешь, чтобы всё решалось
на телефоне. Смешивать нельзя.

### 2. Время жизни функции

Vercel Hobby: Edge-функция обязана **начать отвечать** секунд за 25, обычная serverless — за 10.
Тяжёлая модель с циклом инструментов легко думает дольше.

Спасает стриминг: как только пошёл первый байт, соединение держится дальше. Поэтому —
**открывай SSE-поток сразу**, ещё до того как модель что-то сказала. Хоть комментарием
`: keepalive`, хоть пустым кадром. Если ждать готового ответа и только потом отвечать —
функцию убьют на самом интересном месте.

## Проверить руками

```bash
curl -N https://<мост>/v1/chat/completions \
  -H "Authorization: Bearer $BRIDGE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"model":"any","stream":true,"messages":[{"role":"user","content":"скажи привет"}]}'
```

Должны посыпаться строки `data: {…}` и в конце `data: [DONE]`. Если так — Zephyr заведётся
без единой правки в приложении.

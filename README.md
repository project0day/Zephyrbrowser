## Features

| Area | Highlights |
|---|---|
| **Search** | Google, Yandex, DuckDuckGo, Bing, Brave, Startpage, Ecosia — real favicon logos in the search bar, no text labels |
| **Privacy** | Incognito mode, per-site appearance overrides, cookie / history management, ad-blocking engine |
| **Downloads** | Built-in download manager with torrent support, filterable history, per-file actions |
| **Bookmarks & History** | Swipe-to-delete rows, persistent open-link delivery (avoids lost intents under panel), two feed layouts |
| **VPN** | WireGuard + AmneziaWG dual-backend; import `.conf` profiles directly from storage |
| **QR Scanner** | CameraX + ZXing, flashlight toggle, Wi-Fi credential parsing (SSID/password copy one-tap) |
| **Voice Input** | Offline speech recognition via Vosk (no Google services required), works on microG devices |
| **PDF Viewer** | In-app PDF text extraction and AcroForm field editing (Apache PDFBox port) |
| **AI Assistant** | Integrated AI chat panel; configurable model endpoints via Swarm settings |
| **Home Page** | Quick-access tile grid, recents, bookmarks feeds, live clock variant, custom HTML page support |
| **Theming** | 18 Material 3 color themes + incognito purple gradient; per-site dark/sepia override without DOM pollution |
| **Ad Block** | ABP-compatible rule matcher (`^` separator, `||` anchors, `$domain`, generic selectors) with auto-updating filter lists |

## Tech Stack

- **Language:** Kotlin (mixed with vendored Java for AmneziaWG VPN engine)
- **UI:** Android Views + Material 3 components (no Jetpack Compose)
- **Architecture:** Single-process, `AppCompatActivity` + fragment panels, Room DB for persistence, DataStore for preferences
- **WebView:** Android System WebView via `androidx.webkit`
- **Networking:** OkHttp-backed requests for filters, VPN configs, downloads
- **Build:** AGP 8.4.2 · Gradle 8.10 · KSP (not KAPT) · R8 shrinking

## Requirements

- Android 7.0 (API 24) minimum
- Android 14 (API 34) target
- ~40 MB installed size (arm64-v8a + armeabi-v7a native libs included)

## Building

### Prerequisites

```bash
# Install Android SDK command-line tools or use Android Studio's bundled SDK
sdkmanager "platforms;android-34" "build-tools;34.0.0"
```

### Build unsigned release APK

```bash
git clone https://github.com/project0day/Zephyrbrowser.git
cd Zephyrbrowser
chmod +x ./gradlew
./gradlew assembleRelease
```

The unsigned release APK lands at:

```
app/build/outputs/apk/release/app-release.apk
```

### Sign locally (optional)

Place a `keystore/keystore.properties` file pointing to your JKS:

```properties
storeFile=../my-release-key.jks
storePassword=your-store-password
keyAlias=my-key-alias
keyPassword=your-key-password
```

Then rebuild — the signing config is read automatically.

## 1.7.23 — что изменилось (сводка)

- **ПОПАП-МЕНЮ — ТЕПЕРЬ ТО САМОЕ МЕНЮ** — в 1.7.22 осветление получали только мелкие системные меню в панелях, а главное меню экрана (⋮ справа сверху со всеми опциями) по-прежнему рисовалось тем же цветом, что и фон главного экрана (атрибут `zBackground` — отсюда «абсолютно один цвет» и «нет разницы»). Теперь главное меню во ВСЕХ темах берёт `zPopupBg` — тот же цвет темы, но осветлённый, БЕЗ обводки/контура, как и просили. Заодно исправлен найденный при аудите косяк 1.7.22: в темах Sepia и Sand попап был ТЕМНЕЕ фона (перепутан знак) — пересчитаны светлее: Sepia #F1E4D0→#F9ECD8, Sand #F6F0DA→#FEF8E2.
- **ЗАКЛАДКИ — КОРЕНЬ БАГА «СПИСОК НЕ ОТКРЫВАЕТСЯ»** — пользовательский тест сузил причину до режима отображения: карточки открываются, список — нет. Открытие ссылки в обоих режимах идёт одним и тем же кодом — значит, ломалась именно ДОСТАВКА ТАПА. Единственное структурное отличие списка: строки обёрнуты в контейнер свайп-удаления, который перехватывал ЛЮБОЕ движение горизонтальнее 12dp — дрожь пальца или быстрый «заметённый» тап гасили жест, строка получала ACTION_CANCEL и клик не срабатывал вовсе (у карточек обёртки нет — поэтому они работали). Теперь перехват только для явного горизонтального жеста (|dx| > 16dp И заметно шире, чем выше) — вертикальный скролл больше не перехватывается, дрожь не гасит тап. Плюс страховка: если обёртка всё же перехватила короткое быстрое движение (<60dp, <400мс) — клик по строке доставляется вручную. Свайп-удаление работает как раньше (порог 90dp). Тот же фикс автоматически улучшает строки Истории, Загрузок и Платежей — обёртка у них общая.
- **ФОТО — ИНЕРЦИЯ В ОДИН ТОЛЧОК** — жалоба «толкаю фото, скользит трудно, надо несколько раз»: три причины тяжелого хода устранены. (1) У OverScroller уменьшена фрикция вдвое (0.015→0.0075) — тот же толчок теперь скользит примерно вдвое дальше и быстрее, один сильный толчок доводит фото до края в любом направлении. (2) Скорость отпускания умножается на 1.3 — толчок получает «резкость». (3) Порог срабатывания инерции снижен 500→320dp/s и VelocityTracker очищается на новом касании — накопленные точки прошлого жеста занижали скорость, из-за чего ленивый толчок вообще не получал инерции и фото мёртво останавливалось.

## 1.7.22 — что изменилось (сводка)

- **ЗАКЛАДКИ/ИСТОРИЯ — ГЛАВНАЯ ПРИЧИНА НАЙДЕНА: ОТКРЫТИЕ БЫЛО В «МЁРТВОМ» СОСТОЯНИИ АКТИВИТИ (белая вкладка / «не открывается»)** — все три предыдущих канала доставки (интент 1.7.20, прямой in-process канал 1.7.21, резерв onResume) объединяло одно: вкладка создавалась и loadUrl() вызывался в тот момент, когда MainActivity находилась в STOPPED-состоянии ПОД панелью закладок/истории (PanelsActivity непрозрачна и накрывает браузер). На оболочке пользователя WebView, созданный и загруженный в остановленной активити, потом так и не начинал рендерить — вкладка открывалась БЕЛОЙ (что пользователь видел как «не открывается» и «открывается, но экран белый»). Теперь открытие откладывается ДО момента фактического onResume — когда окно браузера реально на экране: панель записывает URL (PendingOpen), отдаёт его живому MainActivity, но навигация выполняется ТОЛЬКО при isResumed, иначе остаётся в резерве и срабатывает в onResume (который всегда следует и за onNewIntent, и за onCreate). Тем самым закрыт весь класс проблем «открыть из остановленного состояния»: белые вкладки, потерянные loadUrl, холодный старт по ссылке из других приложений — всё теперь проходит через одну безопасную точку performPanelOpen(). Закрытие панели тоже укреплено: ссылка на PanelsActivity захватывается до поста — панель не может «залипнуть» открытой.
- **ПРОСМОТР ФОТО — ДВОЙНОЙ ТАП ВЕРНУЛСЯ (зум 1x↔2.5x)** — найдены ДВЕ реальные причины исчезновения: (1) GestureDetector обрабатывался ДО блока when — onDoubleTap стартовал анимацию animateTo(), которую тут же в ЭТОМ ЖЕ вызове убивал animate().cancel() ветки ACTION_DOWN (анимация умирала за 0 мс); (2) отпускание второго пальца (ACTION_UP) при scaleX ещё ≈1.0 запускало ветку «микро-зум → вернуть 1x», которая откатывала только что начавшийся зум-ин. Детектор теперь работает ПОСЛЕ when-блока, отмены на ACTION_MOVE пропускают только реальные движения (>10dp от старта жеста — 1px дрожь больше не убивает анимацию), а окно действия двойного тапа (260 мс) защищает её и от ACTION_UP. Двойной тап: 1x → 2.5x в точке тапа, обратно → 1x.
- **ПРОСМОТР ФОТО — ИНЕРЦИЯ ПАНА («сильно толкнул — фото само доезжает до края»)** — флинг не работал: (1) он был под запретом !wasPinch — жест «щипок → не отпуская палец → толкнул» никогда не получал инерцию; (2) главное — анимация флинга полагалась на computeScroll(), который оболочки некоторых устройств для обычного View просто не вызывают — скроллер стоял на месте, и фото приходилось тащить 2–3 приёмами. Теперь: запрет !wasPinch убран (скорость отпускания = намерение пользователя), порог снижен 700→500 dp/s, а анимация гоняется самораскручивающимся циклом postOnAnimation (flingTick) — не зависит от того, вызывает ли система computeScroll; порог/маршрут одинаково работают на любом устройстве. Пан по-прежнему 1:1 с клампом по реальным границам фото (FIT_CENTER-aware).
- **ПОПАП-МЕНЮ ВО ВСЕХ ТЕМАХ — ФОН СВЕТЛЕЕ НА ~3.5% (без контура)** — пользователь: «именно меню оставь того же цвета, но буквально на 3% светлее — без всяких обводок». Введён новый атрибут темы zPopupBg = поверхность темы, осветлённая на 3.5% к белому (для чисто белых тем — без изменений, светлее некуда), и общий фон попапов z_popup_menu_bg (скругление 12dp, БЕЗ обводки — тень окна следует форме). Переопределены все три пути, по которым Android берёт фон всплывающих меню: android:listPopupWindowStyle (framework PopupMenu — все меню ⋮ в панелях и плеерах), popupMenuStyle/popupMenuBackground (AppCompat/Material). Покрыты все 20 тем: базовая (день/ночь автоматически), Dark #292929, AMOLED #090909, Sepia, Slate, Rose, Forest, Ocean, Plum, Sand, Midnight, Porcelain, Aurora, Crimson, Mono, Mint, Sunset, Violet Night, Player.

## 1.7.21 — что изменилось (сводка)

- **ЗАКЛАДКИ/ИСТОРИЯ — ТАП ОТКРЫВАЕТ СТРАНИЦУ ТЕПЕРЬ ГАРАНТИРОВАННО (новый основной канал доставки)** — предыдущий резерв (1.7.20) покрывал потерю интента, но всё ещё зависел от оболочки: URL ехал к MainActivity через ACTION_VIEW-интент, а onNewIntent для singleTask+REORDER_TO_FRONT некоторые оболочки теряют. Теперь панель передает URL В ЖИВОЙ MainActivity НАПРЯМУЮ — тот же процесс, ноль системы интентов в доставке ссылки (PendingOpen.deliver →MainActivity.openFromPanelDirect): вкладка создаётся и грузится ещё ДО того, как интент вообще отправлен. Сам интент остаётся только сигналом «выйти на передний план» БЕЗ полезной нагрузки — терять больше нечему; полный ACTION_VIEW-интент сохранён как запасной путь (если MainActivity мёртв). Поверх: (1) try/catch-броня вокруг открытия в onNewIntent — сбой navigate() больше не может уронить процесс; (2) прямой канал закрывает переключатель вкладок перед открытием — страница гарантированно видна; (3) в прямой канал и путь резервной записи добавлена защита от двойного открытия. Действует для закладок (тап, «открыть в новой вкладке», «открыть в текущей») и истории.
- **ПРОСМОТР ФОТО — ПАНОРАМИРОВАНИЕ В УВЕЛИЧЕННОМ СОСТОЯНИИ СТАЛО ОТЗЫВЧИВЫМ («тяжело двигается» устранено)** — найден источник тугого пана: координаты середины двух пальцев прогонялись через усреднение по всей пачке событий (1–2 кадра задержки) ПЛЮС экспоненциальный фильтр α=0.55 (ещё ~1.5 кадра) — фото догоняло пальцы с суммарной задержкой ~3 кадров и ощущалось «налипшим/тяжелым» при перетаскивании влево-вправо. Теперь SPAN (дистанция пальцев = зум) сглаживается как раньше — зум остался плавным и без дрожи, — а MIDPOINT (перетаскивание) берётся по концевой точке пачки (там, где пальцы СЕЙЧАС) с быстрым фильтром α=0.75: пан следует за пальцами практически 1:1 (~0.3 кадра задержки). Однопальцевое панорамирование было и остаётся 1:1 с инерцией.
- **ПРОСМОТР ФОТО — КЛАМП ПАНА ПО ГЕОМЕТРИИ КАРТИНКИ (FIT_CENTER-aware)** — границы перетаскивания считались от размеров экрана (width·(s−1)/2), что неверно для фото с полосами (letterbox): картинку можно было утащить глубоко в пустую зону, где она «терялась» и с трудом возвращалась. Теперь свободный ход по каждой оси считается от РЕАЛЬНО ОТРИСОВАННОГО размера фото (вписанного в экран с учётом пропорций) — мёртвых зон нет ни у горизонтальных, ни у вертикальных фото, на любом масштабе; то же для инерционного флинга, пружинного возврата и анимации двойного тапа.

## 1.7.20 — что изменилось (сводка)

- **ПРОСМОТР ФОТО — ФИКС «РАЗДЕЛЕНИЯ ФОТО НА ДВЕ» ПРИ ДЕ-ЗУМЕ** — найден настоящий источник: ImageDecoder по умолчанию отдаёт HARDWARE-битмап, а на ряде GPU сильно промасштабированный hardware-битмап (зум до 8x — это квад >16000 px) драйвер рвёт на тайлы, тайлы съезжают — фото визуально раскалывается/дублируется и «разлетается». Декодирование переведено на ALLOCATOR_SOFTWARE: обычный битмап = одна текстура, один квад — рваться нечему. Побочно это же убирает и остаточные артефакты при зуме.
- **ПРОСМОТР ФОТО — ДОБИТА ОСТАТОЧНАЯ ДРОЖЬ ПРИ ЗУМЕ** — координаты двух пальцев шумят сильнее одного (дигитайзер интерполирует оба контакта), и прежний вариант вёл картинку за шумящим midpoint 1:1. Теперь входы жеста усредняются по всей пачке событий кадра (включая historical-сэмплы) и мягко экспоненциально сглаживаются (α≈0.55 — около кадра задержки, не ощущается); зум остаётся мгновенным и «прилипшим» к пальцам, но дрожь уходит.
- **ПРОСМОТР ФОТО — МЯГКИЙ ВОЗВРАТ НИЖЕ 1x** — при де-зуме ниже единицы смещение плавно демпфируется к центру: сжатие past 1x аккуратно центрирует фото, а не швыряет его к краю экрана.
- **ВИДЕОПЛЕЕР — ТЕНЬ ПОД ШКАЛОЙ ТЕПЕРЬ ДОХОДИТ ДО КРАЯ ВИДЕО** — градиентная подложка была фоном самой панели: она обрывалась на границах панели, а из-за подъёма панели на 26dp под ней оставалась полоса «голого» видео (видно было: видео → отступ → тень, не доходящая до края). Теперь подложка — отдельный слой ПОД панелью высотой 104dp, тянущийся от панели до самого низа экрана: затемнение плавно доходит до края без разрывов, скрывается вместе с панелью.
- **ЗАКЛАДКИ/ИСТОРИЯ — ТАП СНОВА ОТКРЫВАЕТ СТРАНИЦУ (самоисцеляющийся механизм)** — тап открывает MainActivity через ACTION_VIEW; на некоторых оболочках доставка onNewIntent для singleTask-цели с REORDER_TO_FRONT ПОТЕРЯЛАСЬ — закладка «не открывалась». Добавлен резервный канал PendingOpen: панель запоминает URL ДО startActivity; если интент дошёл и был обработан — резерв сбрасывается (двойного открытия нет), а если НЕТ — MainActivity.onResume() сам открывает свежую (до 8 c) запись. Работает и для «открыть в новой вкладке», и для «открыть в текущей».

## 1.7.19 — что изменилось (сводка)

- **ПРОСМОТР ФОТО — ЖЕСТОВЫЙ СЛОЙ ЗУМА ПЕРЕПИСАН ПОЛНОСТЬЮ (вибрация и тугой зум устранены на уровне механики, а не заплаткой)** — выяснено, почему после 1.7.18 дрожь осталась: старый зум стоял на системном ScaleGestureDetector, который (1) считает масштаб ИНКРЕМЕНТАЛЬНО — «насколько пальцы сдвинулись за последний тик» — из-за чего естественная микродрожь пальцев накапливается в видимую вибрацию картинки; (2) не начинает зум, пока пальцы не разойдутся на внутренний порог фреймворка (~27 мм!) — отсюда ощущение «туго, не легко идёт»; (3) на каждом кадре дрался за картинку с пан-клампом на границах (пила); (4) при опускании пальца сразу после щипка срабатывал двойной тап и картинку дёргало к 2.5x прямо посреди жеста. Новый зум — «жёсткий» и абсолютный: масштаб считается из ПОЛНОГО расстояния между пальцами (span-отношение, без накопления ошибки), точка фото под серединой пальцев ЖЁСТКО приклеена к ней — фото буквально липнет к пальцам, зум и перемещение работают ОДНОВРЕМЕННО двумя пальцами, зум стартует мгновенно (порога нет вовсе), во время щипка ничего не клампится (фото свободно, при отпускании мягко пружинит в границы), ложный двойной тап после щипка подавлен (400 мс). Бонусы: диапазон зума поднят до 8x (было 5x), инерционный флинг при панорамировании увеличенного фото, микро-зум (<1.06x) на отпускании сам аккуратно возвращается к 1x. Двойной тап 1x ↔ 2.5x и свайп-перелистывание фото сохранены (свайп подавляется, если в жесте был пинч — фото больше не «улетает» при попытке зума).

## 1.7.8 — что изменилось (сводка)

Новый матчер (семантика проверена 30-тестовым прогоном по реальным формам EasyList/AdGuard до портирования): `^`-сепаратор по спецификации ABP, `||`/`|` якоря, `*` wildcard, $domain=/$important/$badfilter/$third-party, hosts-файлы (0.0.0.0 домен), `#@#`-исключения скрытия, процедурные селекторы (:has() и пр.) и неподдерживаемые опции честно пропускаются вместо поломки. РЕЖИМЫ УБРАНЫ: один тумблер вкл/выкл, все Ютуб-пункты из настроек убраны. Списки фильтров сами обновляются, если старше 3 дней. - **Резервная копия — ОТДЕЛЬНЫЙ экран в Настройках** (пункт из «Основных» убран): что включать (закладки/быстрые плитки/история/настройки/**VPN-конфигурации** — .conf архивируются в JSON), **автобэкап раз в неделю в Downloads/Zephyr + уведомление** (самовозобновляющийся будильник + Boot/MY_PACKAGE_REPLACED ресиверы), штамп «Последняя копия», ручной экспорт/импорт SAF.
- **Настройки — личные данные по полочкам**: новая группа «Личные данные» — Пароли, Автозаполнение, Платёжные данные, Скрипты — каждый открывает СВОЁ окно (раньше только из попапа меню); «Данные и панели» пополнилась Оффлайн-страницами и Резервной копией.
- **Перевод БЕЗ гугл-обёртки — инъекционный**: в системное меню выделения текста добавлен пункт «Перевести» — перевод летит в приложении (translate.googleapis.com ajax с автодетектом → MyMemory как резерв), ничего не открывается и не навигируется; диалог с результатом + кнопка «Копировать перевод».
- **Ночной режим по расписанию**: Настройки → Внешний вид — окно «Начало/Конец» (Material TimePicker); при входе в окно тема приложения и вид страниц автоматически темнеют (дневные значения сохраняются и восстанавливаются утром); минутный тикер работает, пока браузер на экране, и догоняет расписание при возврате/запуске.
- **Группы вкладок в переключателе**: длинный тап по карточке → «Добавить в группу» (новая/существующая/убрать); группы рисуются секциями с заголовком, счётчиком и кнопкой «Закрыть группу»; состав групп сохраняется в сессии (переживает перезапуск).
- **Оффлайн-страницы — «сохранить для чтения без сети»**: пункт в меню сохраняет текущую страницу как web-архив (.mht в приватном каталоге); панель «Оффлайн-страницы» (меню + настройки) открывает копии без сети (file-доступ выдаётся ТОЛЬКО нашему каталогу), «Открыть в сети» — оригинальный URL, удаление чистит и файл, и запись.
- **Фото-загрузки — найден виновник «скачалось мобильным загрузчиком»**: page-fetch резерв шёл с `credentials:'include'`, а публичные CDN картинок (gstatic и т.п.) отвечают `Access-Control-Allow-Origin:*`, который ЗАПРЕЩЁН вместе с credentials — fetch умирал на CORS и файл падал системному DownloadManager'у («встроенный мобильный загрузчик»). Теперь fetch идёт БЕЗ credentials (принимается всеми ACAO:* CDN) и только при неудаче повторяется с ними; имена вида image_ГГГГММДД_ЧЧММСС (сниффинг добавит .jpg/.webp); системный резерв теперь пишет в ПУБЛИЧНЫЙ Downloads и журналируется в нашей панели загрузок (ресивер ACTION_DOWNLOAD_COMPLETE финализирует запись).
- **Внешний вид страницы — фикс «Выбор действует только для сайта google.com»**: хост для посайтового пикера теперь берётся из ЖИВОГО URL WebView (снапшот мог ещё держать прошлую страницу сразу после навигации — отсюда и google.com на Википедии); диалог с главной честно поясняет: «это выбор по умолчанию для ВСЕХ сайтов — sepia с главной и появлялась потом на YouTube; откройте нужный сайт, чтобы настроить только его».
- **Жесты по краям — убрана тень**: плавающая стрелка-пилюля теперь плоская (elevation=0, без drop-shadow).

## 1.7.5 — что изменилось (сводка)

- **«Очистить данные» — переработан целиком**: своя шапка с кнопкой НАЗАД (строится локально — больше не зависит от activity-cast, из-за которого шапка могла пропасть), ряды «чекбокс-слева + иконка + название + подзаголовок» с нормальными отступами и высотой 56dp (пользователь: «пункты впритык к краю, галочки впритык, тонкие»), и главное — **диапазоны времени**: Всё время / Последний час / 6 часов / 12 часов / 24 часа (чипы; история и журнал загрузок удаляются только за период, счётчики подстроены под выбранный диапазон).
- **Тема страницы — ПОСАЙТОВАЯ и честный сброс**: причина «сепия с Википедии утекла на YouTube и не переключалась обратно» найдена — меню-пикер при выборе «Системная/Светлая» внедрял ПУСТОЙ скрипт, и старый тег сепии оставался в DOM навсегда. Теперь: выбор из меню пишется в настройки САЙТА (domain_settings.appearance, миграция БД v3), новый сайт без настройки живёт по глобальной, пункт «Как в настройках» сбрасывает_OVERRIDE_ сайта;WebView перекрашивает свой фон (тёмный/сепия) — белых вспышек при загрузке и переводе больше нет.
- **Перевод страниц — три фикса**: главная страница НЕ переводится вообще (раньше: перекидывало на прошлую страницу → translate.google отказывался от about:home → «Can't translate this page») — теперь тихий тост «Главная страница не переводится»; повторный перевод уже переведённой страницы перезапускает перевод ИСХОДНОГО URL (без вложенных обёрток); фон WebView следует теме — «побеление» во время перевода исчезло.
- **VPN-экран почищен**: тап по hero-кнопке без профилей больше НЕ показывает тост «импортируйте .ovpn» — сразу открывается системный пикер импорта .conf; строка «Встроенный DNS» убрана с VPN-экрана (у DNS свой экран в настройках); все остаточные строки .ovpn в 3 локалях переписаны на .conf (WireGuard/Amnezia).
- **Загрузки — фото скачиваются железно**: трёхступенчатый конвейер: (1) нативный движок → (2) если не смог — ТОТ ЖЕ URL скачивается fetch-ем ВНУТРИ страницы (настоящий сетевой стек браузера: куки, TLS-отпечаток, HTTP/2 — именно его принимают CDN, которые 403-ят наш HttpURLConnection) → base64 → мост → сохранение; (3) последний резерв — системный DownloadManager со своим уведомлением. Плюс сторожевой таймер 20с и дедупликация.
- **Дублирующийся выбор «Открыть в приложении» устранён**: после выбора «Открыть в браузере» хост запоминается ДО КОНЦА СЕССИИ — редирект-цепочка сразу после выбора (youtube.com → consent.youtube.com → m.youtube.com) больше не спрашивает второй раз.
- **Вкладки — превью главной**: у карточки главной вкладки брендированный мок-ап дорисован (поле поиска, круглая «Z», ряд кружков недавних, полосы недавних — раньше был «сплошной фон»); лого чужого сайта (Википедия) больше не может оказаться на карточке главной — превью с диска сверяется с URL вкладки по sidecar-файлу (stale-картинки от старых id отбраковываются), в подписи главной — метка Zephyr.
- **Favicon в омнибоксе — пуленепробиваемо**: иконка принудительно перерисовывается на каждом изменении URL/заголовка (буквенный аватар сразу, сетевое обновление только при совпадении ключа) — иконка прошлого сайта физически не может пережить навигацию (был баг: на странице результатов Google висела иконка YouTube до входа на сайт).
- **«Проверьте подключение к интернету»**: генераторы 204/connecttest/captive-portal проб НЕ блокируются никогда (ни сетевым адблоком, ни кастомными списками) — проглоченная проба заставляла YouTube думать, что сети нет; проверены все вентили: при выключенном адблоке не инжектится ВООБЩЕ ничего (нет хуков, нет CSS, нет перехвата) — «выключено» означает выключено.
- **НОВОЕ — жесты по краям** (обещанные!): свайп от ЛЕВОГО края экрана — назад, от ПРАВОГО — вперёд; события идут в страницу как обычно, пока жест не подтверждён (горизонталь 2:1 + порог), затем поток перехватывается; плавающая стрелка-пилюля растёт при протяжке; зоны исключены из системных жестов (API 29+); тумблер в Настройки → Основное → Жесты.
- **НОВОЕ — экспорт/импорт данных** (обещанные!): Настройки → Основное → Резервная копия: Экспорт (закладки с папками, быстрый доступ, история и ~40 настроек в один JSON через SAF) / Импорт (merge-safe: без дублей, папки восстанавливаются по имени).
- **Скрипты — по ссылке**: кнопка «windows-каталога» с пресетами УДАЛЕНА (пользователь: «пресеты топорные — убери»), сам ScriptCatalog.kt удалён из проекта; «Добавить скрипт» теперь выбор: Новый скрипт / Из файла (.user.js) / **По ссылке** — .user.js скачивается по URL и открывается в редакторе-просмотре (метаданные Tampermonkey парсятся, имя подставляется).

## 1.7.4 — что изменилось (сводка)

- **YouTube: старт видео без ожидания** (главный фикс): найдена причина «кружка загрузки 3–10+ секунд» — JSON.parse-хирургия v3 не видела тела, которые парсит сам БРАУЗЕР (fetch().json() и XHR responseType:'json' обходят page-level JSON.parse). Плеер успевал запланировать преролл → запрашивал рекламу → получал пустой ответ → ждал свой таймаут. Адблок **v4** использует технику uBlock Origin (xml-prune / playlist-json modification): ответы `/youtubei/v1/…` обрезаются ДО того, как плеер их прочитает — fetch-hook (clone → parse → strip → new Response), XHR-hook (переопределение геттеров responseText/response на прототипе — работает и для responseType:'json', лениво с кэшем на запрос) и ловушка ytInitialPlayerResponse через defineProperty-сеттер на document-start (инлайн-ответ в HTML тоже чистится). adPlacements/adSlots/playerAds/adSlotsHeader/adBreakHeartbeatParams удаляются — реклама вообще не планируется, видео стартует сразу. Прошлые слои (фальшивый VAST, JSON.parse-хирургия, CSS, авто-скип, буст) остались как запасные.
- **Звук YouTube больше не играет в фоне**: при выходе из приложения (Home) и при уходе на домашний экран браузера все `<video>/<audio>` во ВСЕХ вкладках останавливаются через JS (+ pauseVideo у YT-плеера), фуллскрин сворачивается — WebView.onPause() один этот случай не закрывал.
- **Загрузки — починен сбой фото**: data:-URI (base64-картинки — то, что многие сайты отдают при долгом тапе «Сохранить изображение») декодируются и сохраняются напрямую, без сети — раньше они мгновенно фейлились с «Загрузка не удалась»; blob:-URL скачиваются через fetch внутри страницы → JS-мост → base64 → нативный движок; HTTP-путь получил Accept/Accept-Language-заголовки, ручной цикл редиректов (HttpURLConnection не ходит через https⇄http — CDN с такими редиректами фейлились) и один тихий ретрай без Referer; записи БД не могут съесть финальное уведомление.
- **«Очистить данные» — защита от вылетов** (пользователь: «либо кидает на главную, либо вылетаю»): всё построение экрана обёрнуто в try/catch с минимальным фолбэком — экран физически не может уронить приложение; MaterialCheckBox заменён на обычный CheckBox; очистка кэша больше НЕ создаёт выброшенный WebView (на части устройств это падало с UnsatisfiedLinkError — Error, который старый catch(Exception) не ловил) — кэш-директории приложения стираются вручную, best-effort.
- **VPN: Cloudflare WARP удалён** (регистрация не проходила, а импорта .conf достаточно): остался чистый премиум-экран WireGuard + AmneziaWG — hero-кнопка, список профилей с бейджами WG/AWG, импорт .conf, kill-switch, split tunneling. WarpManager.kt удалён; существующий warp.conf, если был, остаётся работать как обычный WG-профиль.
- **Вкладки: кнопка «Назад»**: в шапке экрана вкладок слева добавлена явная стрелка назад (тонированная под тему/секцию) — раньше единственным выходом был системный жест.
- **Скрипты — премиум**: «Добавить скрипт» стал акцентной скруглённой кнопкой-пилюлей с иконкой +; **Каталог скриптов дописан до конца** (был просто список + «Отмена»): поиск по названию/описанию/категории, живой счётчик, карточки с иконкой/описанием/категорией и СОСТОЯНИЕМ установки (Установить / Установлен ✓) — тап ставит или удаляет скрипт, список панели обновляется. Каталог вырос с 6 до 10 скриптов (+ скрыть комментарии YT, крупные субтитры YT, чистая выдача Google, открепление шапок сайтов).

## 1.7.2 — что изменилось (сводка)

- **AmneziaWG — нативный движок**: `libawg-go.so` собран из официальных исходников amneziawg-go v3 (4 ABI, Go 1.25 + NDK r27c, runtime-патч boottime), Java-движок `org.amnezia.awg` завендорен (22 класса). Параметры обфускации (Jc/Jmin/Jmax/S1–S4/H1–H4/I1–I5/HeaderProtectionKey…) реально применяются; движок выбирается автоматически по наличию amnezia-ключей в конфиге.

## Сборка

Требуется **JDK 17+** (эталон — Temurin 21) и **Android SDK** (platform 34, build-tools 34.0.0).

1. Создайте `local.properties` с путём к вашему SDK (Android Studio создаст сам при открытии проекта):
   ```properties
   sdk.dir=/путь/к/android-sdk
   ```
   В архив он не включён (машинозависимый).
2. Соберите:
   ```bash
   ./gradlew assembleDebug    # debug
   ./gradlew assembleRelease  # release (подпись из keystore/)
   ```
   Первый запуск скачает Gradle 8.7 и зависимости (нужен интернет).
3. APK появятся в `app/build/outputs/apk/`. Эталонные APK версий 1.2.1–1.3.2 лежат в `release/`.
